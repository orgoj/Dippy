## Design Decisions

### Remote Context Propagation
**Decision**: Add `remote: bool` to `HandlerContext` instead of using global state
**Why**: Handlers need to know execution context to make correct decisions. Docker exec runs commands in containers (remote), and those commands shouldn't have paths resolved against host filesystem. HandlerContext is the proper place for this flag since it's passed to all handlers.

### Shell Handler Delegation
**Decision**: Shell handler (`sh -c`) must copy `remote` flag when delegating
**Why**: When `docker exec container sh -c 'cd /app && cat file'` runs, the `sh -c` is already in remote context (inside container). Without copying the flag, the inner command `cd /app && cat file` would be analyzed as if running on host, causing incorrect path resolution.
