### Technical Lessons:

**Dippy Hook Architecture:**
- Tool detection via `tool_name` field in JSON input
- Supported tools: `Bash`, `Write`, `Edit`, `MultiEdit`, `WebSearch`, `mcp__.*`
- Each tool type has dedicated handler: `check_command()`, `check_file_tool()`, `check_web_tool()`, `check_mcp_tool()`
- PostToolUse handlers: `handle_post_tool_use()`, `handle_web_post_tool_use()`, `handle_mcp_post_tool_use()`

### Process Lessons:

**Merge Report Best Practices:**
- Include git hash and date in filename for future reference
- Separate "what we added" from "what upstream added"
- Provide verification commands that can be re-run
- Document both technical and behavioral changes

**README Accuracy:**
- Don't assume features are fork-specific without verification
- Check git history: `git log --oneline original/main..HEAD`
- Verify claims with actual code/data, not memory

**Configuration Completeness:**
- When using hooks, verify ALL supported matchers are configured
- Missing matchers = silently ignored tool types
- Read tool code to understand full capabilities
