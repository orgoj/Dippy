## Task Summary
User wanted to validate complex shell commands with dippy using a custom wrapper `run-on-server` for lnav log analysis commands. The goal was to enforce a strict format pattern for lnav calls that include SQL queries and write-table-to output.

## Work Done
- Investigated how dippy wrapper system works with complex quoted commands
- Discovered that Parable parser strips outer quotes, affecting pattern matching
- Found that `["]*["]` character class patterns don't work because quotes are stripped
- Created working configuration with deny/allow rule combination
- Added 5 new tests to `tests/test_custom_wrappers.py` for lnav wrapper validation
- Committed and pushed changes to `orgoj-dev` branch

## Design Decisions
- **deny + allow combination**: Used last-match-wins behavior. `deny lnav *` catches all lnav, then `allow` with specific pattern overrides for correct format
- **Pattern without quotes**: Used `lnav -n -c ;* -c :write-table-to -* /log/**log` instead of `["]*["]` because parser strips quotes
- **Message only on deny**: `allow` directives don't support messages (by design), so message goes on `deny` rule

## Challenges & Solutions
| Challenge | Solution |
|-----------|----------|
| User's original pattern `["]*["]` didn't work | Discovered parser strips quotes; use content-based pattern like `;*` instead |
| Message not parsing on allow directive | `allow` doesn't support messages by design; use `deny` with message + `allow` override |
| Understanding wrapper extraction flow | Traced through `_extract_wrapper_args` and `_get_word_value` to understand quote stripping |

## Lessons Learned

### Technical Lessons:
- Parable parser strips quotes from word values via `_strip_quotes()`
- `allow` directive doesn't support messages (only `ask` and `deny` do)
- Custom wrappers work by: parse → `_get_word_value` → `_extract_wrapper_args` → re-parse inner command
- Character class patterns like `["]*["]` won't match content that had quotes stripped
