## Design Decisions
- **Exit code 2 for input errors**: Empty command or missing `--cmd/--stdin` returns exit 2 (ask) rather than 1 (deny), because it's an input error not a rule-based denial
- **Map 'pass' to 'ask' in CLI mode**: "pass" means "let AI decide" which has no meaning in standalone CLI context
- **argparse with mutually exclusive group**: `--cmd` and `--stdin` are mutually exclusive
- **config_path as highest priority**: Explicit `--config` overrides even `$DIPPY_CONFIG` env var
- **Main docs in config.md**: README gets just a mention, full CLI documentation goes in `docs/config.md`

## Lessons Learned

### Technical Lessons:
- Dippy config rules follow "last match wins" and can't override built-in SIMPLE_SAFE commands
- Rule syntax: `deny mycommand *` matches command with any args, `deny mycommand` only matches bare command
- Exit codes should reflect semantic meaning (input error ≠ rule denial)

### Process Lessons:
- When writing config rule tests, use fictional commands to avoid allowlist interference
- Code review subagent is useful for catching issues like inconsistent parameter usage
