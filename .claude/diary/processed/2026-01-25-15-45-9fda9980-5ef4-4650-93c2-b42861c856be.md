## Lessons Learned

### Technical Lessons:

1. **HandlerContext Pattern in CLI Handlers**
   - Correct pattern: `tokens = ctx.tokens` then use `tokens` everywhere
   - Alternative: Use `ctx.tokens` directly consistently
   - Never mix patterns (e.g., `tokens = ctx.tokens` then `ctx.tokens[i]`)

2. **Context Flags Propagation in Decision Trees**
   - Must pass `context_flags` parameter through all analyze functions
   - All `Decision()` constructors should include `context_flags=context_flags`
   - `_combine()` must collect and propagate flags from children
   - Special nodes (pipeline, subshell, list) add their own flags

3. **Test Output Analysis**
   - Expensive commands (pytest, large operations) go to `/tmp/file.txt 2>&1`
   - Check size: `wc -l /tmp/file.txt`
   - Analyze: `grep`, `head`, `tail` on file
   - Never re-run for different views

### Process Lessons:

1. **Evidence-Based Debugging**
   - Scan for actual errors first: `grep "^ERROR" /tmp/output.txt`
   - Identify specific files with bugs
   - Fix ONLY confirmed issues
   - Verify fix addresses the error

2. **Minimal Change Principle**
   - User wants minimal changes, not "complete refactors"
   - One-line fix preferred over systematic changes
   - If changing 80+ files, you're probably wrong

3. **Ask Before Acting**
   - User said "nic dalsiho nedelej" - means STOP, explain first
   - Don't make edits when user asks for explanation
   - Clarify scope before taking action

### To Remember for CLAUDE.md:

1. **Test Execution Discipline**
   - Already documented but CRITICAL: Run expensive commands once to file
   - Consider adding example pattern for pytest analysis

2. **Merge Process**
   - After upstream merge, run tests IMMEDIATELY to baseline
   - Check for NameError/AttributeError patterns (incomplete refactors)
   - Don't assume systematic issues without `grep` evidence
