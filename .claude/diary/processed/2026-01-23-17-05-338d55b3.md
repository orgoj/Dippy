## Design Decisions

### Config Directive Naming
- **Initial:** `set log-standard off`
- **Final:** `set log-hook-approvals off`
- **Why:** User pointed out "log-standard" is too vague. "log-hook-approvals" is explicit about which log file it controls, making it clearer for users.

### Logging Disable Implementation
- **Approach:** Clear root logger handlers and set level to CRITICAL+1
- **Why:** Prevents any logging output without breaking logging calls in code. More robust than just removing handlers.

### Tool Whitelist in Mode Detection
- **Set vs List:** Used `set` for O(1) lookup
- **Why:** Performance - tool detection happens on every hook invocation

## Lessons Learned

### Technical Lessons:

**Claude Code Subagent Bugs:**
- **Issue #4740** - Subagents bypass tool permissions entirely (closed as NOT PLANNED)
- **Issue #4669** - PreToolUse hooks return correct JSON but decisions are ignored (closed as NOT PLANNED)
- **Impact:** Hooks work in main session, completely ignored in subagents (Task tool spawns)
- **Workaround:** Only explicit config rules provide any protection, but even those may be bypassed
- **Status:** Anthropic considers this "not planned" - won't fix

**Audit Log Format:**
- `"decision": "allow", "cmd": "X"` - User approval (no rule matched)
- `"decision": "allow", "cmd": "X", "rule": "pattern"` - Config rule matched
- The presence/absence of `"rule"` field distinguishes the source

**Python Logging Disable:**
```python
root_logger = logging.getLogger()
root_logger.handlers.clear()
root_logger.setLevel(logging.CRITICAL + 1)
```
Complete shutdown of logging system - no output, no file writes.
