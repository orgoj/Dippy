## Design Decisions

### Decision 1: List[str] instead of str for wrapper_context
**Why**: The spec required multiple context flags from wrappers (wrapper name + destination). Changed from single string to list to support `{wrap, server1}` both being added to context flags.

### Decision 2: Analyzer-side wrapper detection (not CLI handlers)
**Why**: CLI handlers are discovered at import time (before config loads). Wrappers are defined in config, so they can't be registered as CLI handlers dynamically. Implemented in `_analyze_simple_command` where config is available.

### Decision 3: Set union for wrapper merging
**Why**: Wrappers from multiple config scopes (user + project) should accumulate without duplicates. Used set union (`|`) in `_merge_configs` to handle this automatically.

### Decision 4: Same option parsing as SSH
**Why**: Custom wrappers follow same pattern as SSH wrapper. Reused the option list (`-b`, `-c`, `-D`, etc.) for consistency and familiarity.

## Mistakes & Corrections

### Where I Made Errors:
- **Initial test expectation error**: In `test_wrapper_specific_over_generic`, I expected the deny rule with both flags `[wrap,server1]` to override the allow rule with just `[wrap]`. This was wrong - last-match-wins applies regardless of flag specificity.
- **Fix**: Changed test to `test_wrapper_last_match_wins_with_flags` and corrected expectation to "allow" since it's the last matching rule.

### What Caused the Mistakes:
- Misunderstanding of rule matching precedence. I assumed more specific flags would win, but the spec clearly states "last-match-wins" for all rules regardless of flag count.

## Lessons Learned

### Technical Lessons:
- **Context flags accumulate**: When wrapper delegates to inner command, context_flags is a union of existing flags AND wrapper_context items
- **Set operations for config merging**: Use set union (`|`) when merging wrapper sets across config scopes
- **Type system consistency**: Changing a field from `str` to `list[str]` requires updating ALL consumers (handlers, analyzer, tests)
