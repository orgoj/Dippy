## Design Decisions

### Config-based wrapper definition
**Decision**: Wrappers defined via `wrapper <name>` directive in .dippy config files
**Why**: KISS principle - simple syntax, project-specific, no code changes needed for new wrappers
**Alternative rejected**: Dynamic CLI handler generation (too complex, hook cache issues)

### Analyzer-side extraction, not CLI handler
**Decision**: Implement wrapper extraction in `_analyze_simple_command` in analyzer.py
**Why**: CLI handlers discovered at import time (before config loads), wrappes defined in config - timing mismatch
**Alternative rejected**: Dynamic CLI handler modules (hook cache issue in Claude Code)

### wrapper_context type change: str → list[str]
**Decision**: Change from `wrapper_context: str | None` to `wrapper_context: list[str] | None`
**Why**: Single wrapper produces TWO flags (wrapper name + destination), existing ssh/sudo produce one flag
**Backward compatibility**: Must update ssh.py and sudo.py handlers to return list: `["ssh"]`, `["sudo"]`

### Two-flag system for wrappery
**Decision**: Wrapper creates context flags: `[wrapper_name, destination]`
**Why**: Allows granular rules like `allow [server1] free *` (specific server) OR `allow [ssh] *` (any SSH)
**Alternative considered**: Combined flag like `ssh:server1` (rejected - less flexible)

## Challenges & Solutions

| Challenge | Solution |
|-----------|----------|
| How to detect wrappery before config loads? | Don't use CLI handler - check `tokens[0] in config.wrappers` in analyzer |
| How to support multiple flags from one wrapper? | Change wrapper_context to list[str], add all items to context_flags |
| How to handle wrapper without destination? | Return Classification("ask") - treat as interactive session |
| How to skip options before destination? | Reuse ssh.py logic: skip opts with arguments, first non-option is destination |
