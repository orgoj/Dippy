## Design Decisions

### Last match wins semantics
Dippy uses "last match wins" (like git config) to allow local project configs to override global user configs. Trade-off: intuitive for config layering, but counterintuitive within single file where you'd expect `allow specific; deny *` pattern.

## Lessons Learned

### Technical Lessons:
- Dippy uses "last match wins" - general rules go FIRST, specific exceptions go LAST
- Rule order: `deny mkdir *` then `allow mkdir -p ./**` (not the reverse!)
- `_match_words()` returns last matching rule, not first
- Config merge is `base.rules + overlay.rules` - global then local

### Process Lessons:
- When debugging config matching, trace through actual code path
- Check documentation for consistency when finding semantic issues
