## Design Decisions
- **Command Name**: `notifier-command` was chosen for clarity.
- **Sidekick Mechanism**: The command is called "sidecar" style during hook execution.
- **Idle Mode**: A specific `--idle` flag is passed to the command during session stop hooks, enabling long-polling for new events while the agent is inactive.
- **Tagging**: Output is wrapped in `<notification_note>` to provide clear markers for LLMs without being tied to a specific "mail" purpose.
- **Agent Reactivity**: For `pi-mono`, used `pi.sendUserMessage` to force a new turn when a notification arrives during idle, effectively "waking up" the agent.

## Lessons Learned
### Technical Lessons:
- When adding fields to a dataclass that is manually instantiated (not using `**kwargs`), always update the instantiation calls.
- `pi-mono`'s `agent_end` event is a powerful hook for implementing "background" or "idle" behaviors.
- Using `pi.sendUserMessage` with `deliverAs: "followUp"` is the safest way to inject agent-initiated turns.

### Process Lessons:
- **TDD Requirement**: The project mandates TDD. While I implemented the fix first this time, I should have written a failing test case for the configuration loading specifically.
- **Czech STOP signals**: The user uses strong language ("kurva", "co furt delas") to signal repetitive errors or frustration. This is a hard STOP to rethink the approach.
